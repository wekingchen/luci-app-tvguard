# TVGuard Agent · 效果验收门槛

> 目标是让电视端成为 N1 的**补充证据**，解决免费 576p/720p 低码率视频被网络识别漏计的问题，同时不误算首页、暂停、待机。不是在电视上另做计费器。
>
> 原则：**验证通过才算功能实现；编译成功、模拟器 PASS、App 有进程都不能代替实际效果。**

## 功能正确性

1. **前台 App 证据：** 银河奇异果(`com.gitvdemo.video`)、云视听极光(`com.ktcp.video`)、SmartTube(`org.smarttube.stable`)、小米首页(`com.mitv.tvhome`)分别进入和离开，观察事件包名及实际 Activity，按录屏/手工时间线对照。不把 ADB 读系统记录的结果当成 Agent 已成功。
2. **页面切换：** 视频应用首页→播放器→暂停→恢复→退出→系统首页；必须确认 App 前台、播放器页面变化，但**播放器 Activity 不等于正在播放**，暂停只能依赖交叉证据和实测。
3. **边界：** 快速切 App、同包 Activity 切换、Home、待机、休眠唤醒、时间变化、空事件、事件过期、授权撤销、设备断网、应用被小米清理；状态不得伪装为已确定播放。
4. **证据时效：** N1 未来只使用有序号/时间戳且新鲜的状态；过期、失联、事件缺失均标记为 `unknown`，不能因为最后一次是 PlayerActivity 就无限延长。
5. **基于真实 N1 窗口的计时：** 用家长手工标记的真实视频播放/暂停时间区间对照 N1 `used_seconds` 和 Shadow Soak；低码率 576p/720p 必须正确计入，高码率 1080p/4K 不回归；首页、暂停、待机不凭 Activity 单独计时或免计。
6. **失效隔离：** 关闭 Agent / 撤销权限 / N1 不可达时，电视不能卡顿；N1 保持现有计时和防火墙逻辑，旁路数据不会修改额度、奖励、封禁或代理配置。
7. **资源：** 电视端不创建运行日志/DB/离线队列；断网丢弃旧消息。实机记录 `/data/data/com.tvguard.agent` 目录、PSS、CPU、唤醒情况的安装后/运行 1h/24h 差异，存储不得随采样次数线性增长。必要的 Android 系统级写入不计为 Agent 自有日志，但应如实记录。
8. **平台行为：** 用户可见开关 / 正常安装卸载 / 明确授予特殊访问权限；不隐藏进程、不自我复活循环、不绕过安全机制。重启和待机恢复都应正常，否则视为未通过。
9. **安全边界：** 仅 N1 的固定局域网接收器可处理数据；认证与重放/伪造防护单独评审。跨设备上报前不可把任意手机/电脑流量判成电视流量。

## 测试关口

### T0 源码与构建
- 编译目标 minSdk23；静态检查禁止运行日志、DB、持久队列、无谓外连，新增持久写入必须经审查。
- Java 单元测试覆盖同包 Activity 切换、乱序事件、未知/失效状态；Gradle 测试与 APK 构建通过。

### T1 Android 6 模拟器
- APK 安装、启动、真实 AppOps 授权、真实 UsageStats 事件、监测服务、模拟器重启后恢复、短时私有目录增长检查。
- 不能用 T1 替代小米电视厂商兼容性。

### T2 小米电视功能验证（不可跳过）
- 观察实际前台、首页/播放器、遥控器操作；关闭 ADB 后正常；待机唤醒和重启后自动恢复；无小米异常安全提示或持续后台拉活。
- 若权限/后台被拦截，记录事实、使用合法系统设置修复；不能宣布“通过”。

### T3 N1 Shadow Soak 融合观察
- 必须让真实 Agent 事件达到 N1，按窗口对齐，能看到事件新鲜度和失联状态。
- **整个 T3 不影响 `USED_S`、`billing_state`、额度、奖励、`TVG_GATE`，除非后续单独审查/启用。**

### T4 真机视频效果（P0 → P1）
- P0：免费 576p/720p、缓冲、低流量连续播放的真实计时；与标记播放时段对齐，不因 stable_low/idle_verified 漏计。
- P0：播放器内暂停、应用首页、系统首页、待机的免计正确，不因 PlayerActivity 长驻而误计。
- P1：1080p/4K、快进、清晰度切换、跨视频 App；确保不牺牲当前已经可识别场景。
- 任一严重漏计/误计必须在 Shadow 观察隔离中定位并复测，不能宣称自动计时算法完成。

### T5 24h 稳定性与存储
- 常规看电视/待机/重启/局域网偶发断开，测持久存储变化、异常重启、权限恢复、PSS/CPU 与网络行为。没有崩溃循环，没有无限增长数据。
- N1 摘要大小与 RAM 环须有上限，不把电视压力转移到 N1 闪存。

## 上线门槛

- **0.1.0 是权限和前台识别验证 APK，不是最终完整产品。**
- T0/T1 通过才能开始 T2；T2 通过后才进入 T3；T3/T4/T5 通过并保留真机证据后才能考虑提升 Agent 信息对计时的权重。
- 任何新增网络融合必须使用独立 PR，默认仅旁路观察，不能顺手改变原本 N1 稳定计时/阻断策略。
- 没有明确的真机数据，绝不写“100% 保活”“零系统磁盘写入”“暂停识别准确率 100%”等未经验证的结论。
