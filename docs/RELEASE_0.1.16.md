## r25 · 家长遥控 N1 冷启动自恢复（待实机重启验证）

- 用户确认 r24 在日常使用及本地镜像应用正常，但 N1 某次重启后独立家长遥控服务不可用；手工停用、启用后立即恢复。
- 源码根因候选为 `root/etc/init.d/tvguard-remote`：之前等待 br-lan 地址不存在，只要 `tvguard-remote-lan-ip` 失败便在 procd 实例未关闭前直接 `return 1`；无法保证网络事件后自动恢复。源码问题确定，现场单次事件还需日志核实。
- r25：启动时有限等待 br-lan 私有 IPv4；没拿到时仍先提供 127.0.0.1:18765，不放开 0.0.0.0；netifd `lan` 接口 up/update 后由 procd 重启独立 uhttpd 重新绑定局域网 IP。未启用家长遥控或 LAN 时不会额外启动。
- 状态接口新增 `lan_listener` 真实 HTTP 探测，LuCI 由原来「配置已启用即显示内网可用」改为「真实可用 / 待恢复」区分。
- 新增执行式 Shell 冷启动失败、延迟恢复、禁用开关模拟，保留原有配对、CGI、N1 计时和全库回归。
- 本版尚无 N1 重启后的真实日志，因此不能声称已验证长期或开机稳定性。

## r24 · 仅应用 N1 已下载的 cloudflared 镜像（待 N1 真机验收）

- 前提：Portainer 已把 `cloudflare/cloudflared:latest` 下载到 N1 的本地 Docker 镜像存储。r24 **不访问 Docker Hub/Cloudflare Registry、不调用 docker pull**。
- LuCI「远程访问 → 维护与诊断」新增「本地镜像更新（高级）」，比较当前容器 `.Image` 和本地 latest `.Id`，无更新时按钮禁用且不触发任何 Docker 改动；有本地新镜像时需要用户确认才进行切换。
- `apply-image` 仅在 Token 已配置、XFS 可写、容器为 TVGuard 所有、HTTP/2 正在运行、镜像及其最低版本校验通过时启用；停止的容器和 foreign 同名容器不得触碰。
- 安全更新沿用 r23 已测试事务：停止旧容器，改名备份为 `tvguard-cloudflared-before-local-image`，用本地 latest 建立全新 HTTP/2 容器；检查实际边缘注册日志和新容器镜像 ID 与预期一致，成功才删除备份。失败按原容器 ID、配置及运行状态恢复。独立备份名防止覆盖 r23 历史迁移备份。
- CI 模拟真实控制脚本与 Docker 命令，覆盖没有新镜像、成功更新、失败回退、未知容器、停用态、备份冲突、不触碰其它 Tunnel，并测试 LuCI 按钮权限与 IPK 实物。
- 安装 r24 本身**不会自动替换 HTTP/2 容器镜像**。需在 LuCI 手动点击「应用本地最新镜像」；验证镜像 ID、4 条 `protocol=http2` 注册日志以及 iPhone 外网访问。

## r23 · 仅 TVGuard Tunnel 使用 HTTP/2（待 N1 真机稳定性验证）

- N1 用户日志确认 TVGuard / ntfy 的 QUIC 连接出现 `no recent network activity`、运行中重连，Vaultwarden 通过 HTTP/2 运行相对稳定；N1 的 IPv4/IPv6 回环 DNS 后续查询正常，TVGuard 本地 HTTP 约 2.36ms。证据支持先对 TVGuard 单独进行 TCP 7844 对照。
- 只调整 TVGuard 专用容器启动参数为 `--protocol http2`；使用既有 `--network host`、只读 XFS Token、`--cap-drop ALL`、`no-new-privileges`、Metrics `127.0.0.1:20241`、日志轮转，不改另外两套 Tunnel。
- 已存在的 QUIC / auto 容器无法通过简单 `docker restart` 修改配置。r23 在升级完成时**只对正在运行且所有权标签匹配的 TVGuard 容器**自动迁移；停止的容器保持停止，后续手动启动时再迁移。
- 一次性迁移保留停止的旧容器作为回退副本，必须等新容器日志中注册实际 HTTP/2 边缘连接再清理旧副本；失败时尝试完整恢复旧容器和原运行状态。若旧副本名称已经被占用，则直接拒绝覆盖。
- LuCI 可显示当前容器启动协议（但不冒充 Tunnel 在线健康检查）。独立模拟 Docker 测试覆盖成功、失败、异物、冲突、幂等重启及 Token 不变，打包检查验证真正的安装代码。
- **仍需真机执行**：升级 r23 后查看 `docker inspect ... .Config.Cmd` 是否包含 `--protocol http2`，日志是否出现 `Registered tunnel connection ... protocol=http2`，并用 5G 验证 `https://tv.rqqr.de`。

## 使用方式

1. 基线 r16 已由用户完成多项真机验收；升级 r17 只需 N1 主 IPK，不需要更新已安装的同版电视 Agent。
2. iPhone 已通过 Safari 添加 `https://tv.rqqr.de/` 至主屏幕，并提交 r17 真实界面截图；标题状态栏遮挡已修复。
3. 家里和外面均使用同一公网域名，可避免快捷指令和分流 DNS；如有需要，可保留局域网 HTTP 作为备用。
4. 已配对授权默认长期有效，清除浏览器 Cookie/无痕模式仍可能导致重配；LuCI 可单台撤销或撤销全部。
5. 当前不启用 Cloudflare Access。外网配对页面可被公众打开，**控制操作必须通过 TVGuard 配对授权**；禁止公开 LuCI/RPCD/SSH/Docker Socket。
