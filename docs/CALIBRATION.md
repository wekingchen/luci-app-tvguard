# 手工校准与影子识别（开发版）

> **不更改电视联网权限，也不自动免计时。** 网络特征可能与电视前台显示不一致，尤其是广告、后台心跳、预加载、代理等。

## 为什么要单独标注应用？

2026-11-08 十场景实测：

- 腾讯极光：正常播放约 180 PPS，暂停约 166 PPS，暂停并未明显降低 UDP 包频率。
- 爱奇艺：暂停前期流量较高，最后 30 秒只有约 7 PPS。
- 芒果 TV：播放曾短暂降至 42 PPS，暂停后稳定在 9～14 PPS。
- 小米系统首页约 7 PPS、熄屏 60 秒零包。

这些数值存在重叠。没有任何通用的 PPS 阈值能保证识别“正在播放”。

## 采样方案

当前 LuCI 页面提供“电视应用 + 状态”选择：

- 应用：腾讯极光、爱奇艺、芒果 TV、其他；
- 状态：正常播放、视频暂停、应用首页闲置、小米系统首页闲置、熄屏待机。

点击开始后，每 10 秒采集 **120 秒**，记录为一个独立校准 session。建议同一 App 的同一状态在不同时间至少测三次；实测过程不要切换界面，播放尽量选择不同视频，以检测内容差异。

数据文件（root 权限才能读取）：

`/etc/tvguard/calibration-v3.csv`

列为：

`timestamp,session_id,scene,app,pps,tcp_pps,udp_pps,bytes_per_second`

仅保存聚合数值，不抓取播放内容、不记录网址、DNS、账户信息或电视画面。

## 在电脑上作离线评估

先从 N1 取得数据：

```sh
scp root@192.168.101.99:/etc/tvguard/calibration-v3.csv .
```

然后在已检出仓库并有 Python 3 的电脑上：

```sh
python3 scripts/evaluate-calibration.py calibration-v3.csv
```

分析器使用按 session 留出验证（leave-one-session-out），对比同一 App 的播放和首页闲置/暂停。至少 **3 个独立 120 秒 session**、每次至少 6 个采样点，样本重叠或阈值不稳定时输出 `overlap_or_unstable`；不足输出 `insufficient`。

输出 `separable_shadow_only` 只意味着这些**已标注实验样本中**存在候选可分离特征，不代表可以确定电视前台画面，也**不会为 TV Guard 自动生成免计时规则**。

## 下一阶段验收

在现实家庭环境的不同日期、不同视频和不同背景任务下重复测量。将候选识别先显示为“疑似空闲”，并人工记录误判。只有出现独立证据且误判风险可控，才考虑提供可选的免计时策略。无法确认时继续计时。

**旁路由无法观察绕开 N1 的数据流；没有电视端协作就不可能凭这些统计绝对判断前台。**
